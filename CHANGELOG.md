# Changelog

Every delivered pipeline adds an entry here with its ticket number (`/pipeline:complete`). Tickets live in the private planning repo; old AIC's are cited as "AIC #N".

## Unreleased

### Added

- **The secure form post** (#42, the second slice of #8). `AIC\Form`: `FormGuardMiddleware` checks every POST, PUT, PATCH and DELETE before routing. The CSRF token (the `aic_csrf` field or the `X-AIC-CSRF` header) must match the session's, else 403, and a filled honeypot answers 400. `FormTokens::issue()` gives the session's token, 256 random bits. The `Form` atom takes a `FormToken` and renders the hidden token and the honeypot itself. The demo's forms carry it, and the theme hides the honeypot. `SessionIds` is now `RandomTokens`. gate:23 posts with each site's session and token and checks the guard (27 steps). An unsafe request without a token now answers 403 before routing.
- **Sessions** (#41, the first slice of #8). `AIC\Session`: a session of string values in Postgres (`aic_sessions`, a framework migration), behind a `__Host-aic_session` cookie (Secure, HttpOnly, SameSite=Lax). `SessionMiddleware` loads it, puts it on the request (`RequestSession::read()`), saves it and sets or clears the cookie; an unknown id gets a fresh session. Ids are 256 random bits from `random_int`. The demo's `/visits` counts visits and forgets them. `ResponseBuilder::withAddedHeader()`. gate:23 gains three session steps (24).
- **The project theme** (#39, closing #7 and M3). `theme/` holds ordered plain CSS: tokens with a dark scheme, the document and regions, and the atoms' `aic-*` classes. `composer run build` writes `public/assets/aic.css`, committed and kept fresh by gate:24. The layout links it; DDEV's nginx serves it, a reverse proxy does in production, and the app's `/assets/{file}` route serves it inline for the compiled site (gate:23 compares it, 21 steps). `FileDownload` with an empty name sends no `Content-Disposition`. `RequestedFile` serves both the downloads and the assets.
- **Blocks** (#38, the fourth slice of #7). `AIC\Block\Contracts\Block` is a component with a `Placement` (region, weight, route prefix or everywhere). Blocks are tagged plugins, and `PageHandler` places the matching ones in every page document after the page's own content, lightest first. The demo's `nav` shows a powered-by line everywhere and a note tip under `/notes`. #40 records the elephc gap for `instanceof` narrowing.
- **Layouts and regions** (#37, the third slice of #7). A Page returns `PageDocument(Layout, status)`: the layout names its regions and holds the page's `Regions`, each a checked name and its components, rendered as `<div data-region="name">`. One region renders alone (`Regions::html()`), the unit of #12's fragments. Components sit between `<!--aic:c KEY-->` markers (compile-time keys from templates, explicit keys in loops), and `@if` and `@foreach` between morph markers. `Html` is a component. Every demo page renders through `AppLayout` (`content`, `nav`), natively too. gate:21's bundler now loads a supertype first through a type-hint cycle.
- **Compiled templates** (#36, the second slice of #7). A component's `X.tpl` compiles at build time to `XTemplate.php` beside it: `{{ }}` escaped by default, `{!! !!}` for `Html` only, `@component()`, `@if`/`@else`/`@endif`, `@foreach (… as Type $var)` and `@use`. The generated class passes every gate as written (small chained part methods, typed loop mappers), and a template too big for one class is refused. `composer run build` writes them and gate:24 fails on a stale one. The note page and the note list render through `NoteCard` and `NoteList` templates, natively too.
- **Components and the catalog atoms** (#35, the first slice of #7). `AIC\Component\Contracts\Component::render(): Html`, with `Html` as escape-safe markup. The atoms with a caller (Alert, Badge, Button, Form, FormField, Input, Link, Textarea) render plain markup with `aic-*` class names and one escaping path. The greeting form, the note forms and the note list are built from them. All 142 runtime classes compile natively.
- **Byte ranges and Server-Sent Events** (#25).
  - Downloads honour one `Range`: 206 with `Content-Range`, 416 with `bytes */size`, and 200 with `Accept-Ranges: bytes` otherwise.
  - `EventStream` sends each `ServerEvent` from an `EventSource` as it comes (`text/event-stream`, not cached, not proxy-buffered).
  - The emitter writes bodies in chunks and flushes after each.
  - The demo `/events?count=N` streams ticks, natively and under php-fpm.
  - gate:23 gains the range and event steps (20 steps).
  - elephc's fork gains `flush()`.
- **The surface manifest** (#26). `composer run build` writes the committed `build/surface.json`: every route (method, path, handler, kind) and every console command (name, class, kind), the kinds read from the class's interfaces. gate:24 fails when it is stale. `RouteTable::routes()` exposes the declared routes.
- **The compiled site is the runtime** (#33). FrankenPHP is set aside (Chad).
  - `bootstrap/serve.php` serves one request with fresh state, and `public/index.php` runs it under PHP. DDEV serves that interpreted reference through nginx-fpm; the FrankenPHP add-on, `public/worker.php` and the worker-mode field are gone.
  - **gate:23, the native site:** every runtime class is bundled with `serve.php`, compiled with `elephc --web --web-isolation=pool` and served beside `php -S`. 16 steps are compared (pages, forms, API, download, 404, 405, and a note's create, show, update and delete). The database steps defer when Postgres does not answer.
  - `composer run native:serve` serves the compiled site for a browser.
  - `AIC\Frankenphp` is now `AIC\Sapi`, with `PhpSapiSink`.
  - Route parameters use `$n` group references.
  - The first native run found seven compiler gaps. Three are fixed in the elephc fork: x86_64 interface dispatch argument registers, `preg_replace_callback` on an empty subject, and every PHP regex delimiter.
- **Entities, CRUD from a controller** (#31, closing #6 and M2). `AIC\Entity`: an `EntityType` names a table, its generated key and its fields over a closed `FieldType` (Text, and CreatedAt, set to `now()` at insert). `EntityStore` queries, inserts (returning the key), updates and deletes by key. Unknown or unwritable fields are refused, and a missing key is `EntityNotFoundException`. `EntityQuery` builds `SELECT … WHERE … ORDER BY` with bound values. The demo app maps rows to a typed `Note` and serves `/notes`: list, create, show, edit and delete. A blank title answers 422 with the form, and an unknown note answers 404 (PageDocument gains 404). `Row::int()`. All 119 runtime classes compile natively.
- **Schema and migrations** (#30, the third slice of #6). `AIC\Schema`: a migration is a class with `version()` and `describe(Schema)`, which chains a fluent table builder (`identity`, `string`, `text`, `timestampTz`, `nullable`, `primary`). The builder makes a schema AST over `LogicalType`, compiled to Postgres DDL by `PostgresDdl`. `Migrator` applies pending migrations, each in one transaction with its row in the `aic_migrations` ledger (version, the sha256 of its SQL, applied_at), and reports each as applied, pending or changed. `bin/aic migrate` and `bin/aic migrate:status` run them; the demo migration creates `notes`. The Database contract gains `fetchAll`, `execute` and transactions. All 102 runtime classes compile natively.
- **The Command kind and the console** (#29, the second slice of #6). `AIC\Controller\Contracts\Command` is the fourth kind: `command(CommandInput)` returns the sealed `CommandResult` (lines and an exit code), which writes itself through `CommandWriter`. `AIC\Console\Application\Console` runs a command by name, and answers an unknown one with the usage and exit 2. `bin/aic` is the entry script, with `db:ping [setting]` (a server setting through a bound parameter; exit 1 when the query fails) and `greet [name]` (one line per Greeter plugin). The kinds guards cover Command, each seen to fail on a plant. All 88 runtime classes compile natively.
- **The database connection** (#28, the first slice of #6). `AIC\Database\Contracts\Database::fetchOne()` runs a parameterised query (`?` placeholders) and returns a typed `Row`. `PdoDatabase` opens PDO pgsql on first use and keeps one connection per worker, and a failure is a `QueryException` naming the SQLSTATE. `DatabaseConfig` is typed config from DDEV's `PG*` environment (`config/database.php`). `/api/status` reports the database server's version. gate:3 now counts an `ext-*` require as backing its extension's classes. All 78 runtime classes compile natively.
- **Plugins** (#5, completing M1). `AIC\Container\Application\Container` is the PSR-11 container: `singleton()` factories, `tag(Type::class, Service::class)`, `tagged(Type::class)` in tag order, `freeze()` at boot, and cycle detection. Service providers register through the `ServiceRegistry` contract. AIC's first custom PHPStan rule, `TaggedServiceTypeRule` (gate:8), refuses a tagged service that does not implement its type, and was seen to fail. The greeting page lists the app's two Greeter plugins. 73 runtime classes compile natively.
- **The kinds** (#22, the last slice of #4). Page, Api and Stream (`AIC\Controller\Contracts`) each have one method and their own sealed response: PageDocument (200 or 422) and PageRedirect (303 by default), JsonResponse (a `JsonSerializable` body), FileDownload. A response writes itself through `ResponseWriter` (`Psr7ResponseWriter`), and PageHandler, ApiHandler and StreamHandler adapt each kind to PSR-15. Three phpat guards, each seen to fail: no class is two kinds, no app class is a bare PSR-15 handler, and the responses are sealed. Routes gain POST. The app's entry points are all kinds: the placeholder page with a greeting form (303, or 422 in place), `/api/status` and `/download/{file}`. This closes epic #4: request in, response out, natively compiled, 64 runtime classes.
- **The kernel and the composition root** (#21, the fourth slice of #4). `AIC\Kernel\Application\Kernel::serve()` takes a SAPI request to a response: it extracts through the `RequestExtractor` contract and answers through the PSR-15 stack. Malformed input answers 400 and anything uncaught a plain 500, so no error escapes into FrankenPHP. Wiring is code: `AIC\Kernel\Infrastructure\SapiServices` builds the framework's SAPI and HTTP pieces from the worker's sink, and `App\AppServices` builds the app's handlers, router, stack and kernel. The worker builds both once and emits each response. All 43 runtime classes compile natively.
- **Routing and the PSR-15 stack** (#19, the third slice of #4). Routes are declared in `config/routes.php` (`RouteCollector::onGet()`, `{name}` and `{name:int|slug|uuid|any}` placeholders) and matched by `AIC\Routing\Domain\RouteTable`: the fewest parameters win, HEAD answers on GET routes, and a miss answers 404, or 405 with `Allow`, through `RouteErrorMiddleware`. The router hands the matched handler the request with its parameters as attributes. `AIC\Middleware\Application\MiddlewareStep` chains PSR-15 middleware. `ResponseBuilder` makes responses. The app's first handlers live in `app/Http`, so every gate now runs with no deferral. All 39 runtime classes compile natively.
- **HTTP with typed input** (#20, the second slice of #4). PSR-7 messages and PSR-17 factories (`AIC\Http`), and the SAPI request and response (`AIC\Frankenphp`): the worker narrows `$_SERVER`, the extractor builds the request, and the response goes out through the emitter and a SAPI sink the worker implements. A query or form field is a string, a list or a map of strings; deeper nesting answers 400. Headers are stored flat and refuse line breaks. `mixed` appears only on PSR overrides; semgrep's phpdoc rule gained the `#[Override]` exemption PHPCS has (Chad). All 21 runtime classes compile natively.
- **Typed config** (#18, the first slice of #4). `config/app.php` returns an `AIC\Config\Domain\AppConfig`, a `final readonly` object whose `name` must not be blank. The worker requires the file once, at boot, and renders the name. Config files are analysed like code. `AppConfig` is the first runtime class since #15, so the native gate runs again.

### Changed

- **Dead-code detection** (#15). `shipmonk/dead-code-detector` replaces the abandoned `tomasvotruba/unused-public` in gate:8. It checks methods, constants, enum cases, and properties never read or written; dead cycles and transitively dead methods; and it does not count a call over an unknown type as usage. gate:0 reports no abandoned package. The gate classes lost their `@api` tags, which had hidden their members from both dead-code checks. The detector found the unused `RelativePathComputer` (deleted) and the caller-less `AIC\Routing\Domain\Method` cases (the class waits for #4). gate:21 defers until runtime code returns.

### Fixed

- **Hook checks on long transcripts** (#16). Every early-exit reader fed by a pipe in `.claude/hooks/` and `bin/` (`grep -q`, `grep -m`, `head`; 15 sites in 8 scripts) now reads a here-string or a process substitution, or `awk 'NR == 1'` takes the first line. Under `pipefail` such a pipe fails once its input outgrows the pipe buffer, as PR #11 found in `enforce-completion.sh`. The semgrep rule `aic-no-early-exit-pipe` (gate:15, which now scans the hooks) keeps the pattern out. The completion hook's block message says how to test a block against the transcript; there is no ceiling on repeated blocks.
- **Completion evidence on a long session** (#3, found live). `enforce-completion.sh` piped the session's command list into `grep -q` under `pipefail`. Past the pipe buffer, `grep -q` exits on its first match, `echo` takes SIGPIPE, and the pipeline fails (141), so a gate run that happened read as missing and Stop blocked in a loop. The checks read a here-string now.
- **Memory in Documentation** (#3, found by #15). `/pipeline:complete`'s write scope now includes the project's auto-memory directory. Its memory step writes there, and the scope hook blocked it.
- **Hook project root** (#3, found live). The hooks take the root from `$CLAUDE_PROJECT_DIR`, falling back to the git root. Starting from the session's working directory found the nested planning repo whenever the shell sat in `docs/planning`, and the MCP-config hook then blocked every write.
- **Hook command detection** (#3). Old AIC's hooks recognized only Skill-tool invocations of the workflow commands. A command the user typed is recorded as `<command-name>/…</command-name>`, so it never made a session a pipeline session.
- **Two hook checks that never ran** (#3). The SAST hook's semgrep check looked for `.semgrep.yml` and the quality hook's PHPCS check for `phpcs.xml`; the real files are `semgrep.yml` and `phpcs.xml.dist`.
- **Two template defects** (#3):
  - The pipeline spec template started at `Phase 1 — Plan PASS`, so an unconfirmed plan passed the phase gate.
  - The notes template carried an empty `## AAR` heading, so an AAR that was never written passed the completion hook.
- **phpat rules that never ran** (#2, #14). phpat runs only rule classes registered with the `phpat.test` tag, and old AIC registered none. Built-in classes now count as dependencies, so the no-Swoole rule can fail.
- **Git hooks on old commits** (#2). Only the enabled git hooks are installed. A disabled hook still ran captainhook, which failed on any checkout older than `captainhook.json`.
- **`bin/ticket.sh` fixes** (#1):
  - JSON escapes are kept on update.
  - File modes are kept on every write.
  - A partly invalid update is refused instead of half-applied.
  - Phases are validated, and a reopened ticket drops its `closed` date.
