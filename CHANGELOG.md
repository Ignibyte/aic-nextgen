# Changelog

Every delivered pipeline adds an entry here with its ticket number (`/pipeline:complete`). Tickets live in the private planning repo; old AIC's are cited as "AIC #N".

## Unreleased

### Added

- **The guard judges a write by where it really lands** (#125). Found in #118's proof, where an agent followed a symlinked `vendor/aic/*` into AIC's own repository. Every write the guard sees (an edit, an MCP tool's path, a shell redirect, `cp`, `tee`, `sed -i`) is resolved to its real path, through the deepest existing folder for a new file, and refused at every enforcement level, run or no run, when it lands outside the project or under `vendor/`. Only `/dev/` stays open, so `2>/dev/null` still works. Proved in a scratch app whose `vendor/aic/framework` links back to this repository.

- **The code wiki** (#108). `composer run build` now writes `docs/wiki/`: an index and one page per module, generated whole from the module manifests, `build/surface.json` and the code index, and committed so a reviewer sees in the diff what a change did to a module.
  - **A module page:** namespace, manifest, requires and required by, exports, routes with their kinds, commands, jobs with their schedules, schedules, blocks, migrations in order, plugins, bindings, middleware, protected prefixes, factories, classes by kind folder (components beside their templates and template classes), the framework systems it uses (each linked to its section of `framework/docs/systems.md`), the other modules' classes it uses, and what other modules use of it. Notes go in `modules/<m>/README.md`, which the page links.
  - **The index:** every module with its routes by kind and class count, the requires graph as a mermaid block, every route, command, job and schedule, and a link to the architecture pages.
  - **Freshness:** gate:24 calls any page stale that the build would not write byte for byte, and a page for no module an orphan; the code index is rebuilt in full for it, so a hand-edited index cannot shape a page. A missing architecture page refuses the build.
  - **`bin/aic code:wiki [<module>|<Class>]`** renders a page live, recorded while a run is open. The guard refuses an edit under `docs/wiki/`, and a run that rebuilds pages it did not declare passes the declaration audit.

- **Plan's grounding check** (#118, part 7b of #91). Plan cannot pass until the engine, on a code index it rebuilds in full each attempt, finds the plan grounded.
  - **Real:** every File Manifest row is one file path with `create`, `modify` or `delete`; a modify or delete row names a file git lists; a create row names a path that is not there; no path appears twice; every Entry Points class exists or a create row makes it (by PSR-4, or the module convention for a new module).
  - **Looked:** the run's own `code.queried` events at plan show at least one `code:tree`, a lookup of every file it modifies or deletes and every existing class it names, an outline of each created file's area, and a `code:search` before each new class. A `code:refs` answer now counts for its subject's file only.
  - **Verdicts:** every reason at once, each naming the lookup to run; a miss is the agent's and spends no retry budget, and counts the lookups so far so new ones are progress; an index or event log the engine cannot read holds the run for the operator.
  - **The wall:** `var/index/` joins the guard's protected paths; a row hand-written into the index does not survive the rebuild.
  - **The proof:** each criterion planted in a scratch copy through the real guard and index, and a live session whose lookups grounded its plan.

- **Inspect commands for agents** (#109, part 1). `bin/aic` answers what the app declares, from `build/surface.json`, without booting the app or opening the database.
  - **The commands:** `route:list [<module>] [--kind=<Kind>]`, `command:list` (each command `runtime` or `dev`), `job:list` (with the schedules that queue each job), `schedule:list`, `module:list` (requires, dependents, counts), `module:show <name>` (the manifest as declared, with each export's users from the code index) and `kind:list` (contract, method, response, folder, count). They are dev-only, in `aic/workflow`: an install with `--no-dev` has none of them.
  - **Output:** plain text in columns, or with `--json` one `aic.console/1` envelope on one line, described by `workflow/schema/console.v1.json`. An unknown flag, a missing value or a wrong count of arguments exits 2 with the usage line; nothing found exits 1.
  - **The surface** now records each command's, job's and schedule's module, each module's bindings, middleware, protected prefixes and factories, and a `kinds` table. A manifest newer than the surface puts a stale line first.
  - **The record:** while a run is open, every lookup is a `code.queried` event; `module:show` names its module as the scope and the manifest and its classes as the files.
  - `CommandInput::arguments()` gives a command all its arguments; it compiles natively with the rest of the runtime.

- **Workflow modes and holds** (#117, part 3b of #91). A run is agentic or interactive, the agent can ask the operator a question, and a row the agent cannot clear goes to the operator instead of holding Stop forever.
  - **Modes:** `config/workflow.php` gains `mode` (Agentic, the default, or Interactive) and `humanComplete` (false), both frozen into run.json at begin. Interactive waits for the operator to confirm every phase exit; `humanComplete` makes an agentic run wait at complete. A confirmation waits as `paused` (exit 1) with the question in `awaiting`.
  - **Questions:** `bin/aic workflow:ask "<question>"` is the agent's; `bin/aic workflow:answer advance|stay ["<note>"]` or `"<answer>"` is the operator's, from a terminal only, refused in the agent's shell. Every answer is appended to run.json's `qa_history`; `question.asked` and `question.answered` join the event schema. An `advance` binds to the tree it was asked about, so an edit after the pause asks again. While a question waits, every write in the project is refused.
  - **The stall rule:** a holding row that repeats once with nothing changed (same check, status and words, same subject and spec) becomes `held` for the operator, so Stop releases.
  - **Stop by mode:** hard holds every run mid-phase; soft holds an agentic run and nudges an interactive one once; off lets it end.
  - **The shell wall** lets read-only git (`status`, `diff`, `log`, `show`, `check-ignore` and the rest, with no `-c`, `--output` or pager) and `sed -n <line>p` read protected paths; `find -fprint` and `-fls` are writes. It refuses php that loads the project's autoloader or names the workflow package (inline code, `auto_prepend_file`, a heredoc, a script); `bin/aic`, `php -l` and `php -S` serving the app (router `public/index.php` or `bootstrap/serve.php`, or `-t public`) pass, and any other server is refused.
  - **The proof:** a scratch project took each criterion through the shim and `bin/aic`, and one live headless session asked, ended its turn, and after the operator's answer wrote it into its spec.

- **AIC's architecture documents, part 1, and gate:29** (#107). `aic/framework` now ships `framework/docs/`, which an app's agent reads at `vendor/aic/framework/docs/README.md` before it builds.
  - **The pages:** the README (what AIC is, the reading order), `kinds.md` (the five entry kinds and the other kinds), `systems.md` (the ten systems, their namespaces, the layer ladder), `modules.md` (the manifest and every declaration, the build, the folders, exports and requires, assets), `gates.md` (every gate and its usual fix) and `conventions.md` (the code rules, each with its gate). They are written for an app: no ticket numbers, no AIC process.
  - **gate:29** fails the set when a page and the code disagree: a gate missing from gates.md or CONSTITUTION §0, an entry kind with no heading, a module folder missing from the table, a namespace in no system section or in two, a manifest declaration never named, an `AIC\…` name, `gate:N` or `composer run` script that does not exist, an anchor no heading answers, an unlinked page, a banned word, or more than two em dashes on a page. It runs in AIC's repo only.
  - **gate:15** now scans `framework/docs/` (its `docs` exclude matched any path part; it is anchored to the root) with two new rules: no AIC process names and no ticket numbers in the set.
  - **The pack** points the app's agent at the docs: the AGENTS block's new item 4 and the plan skill name `{vendor}/aic/framework/docs/README.md`.
  - **The proof:** each of gate:29's checks failed by name on a planted violation (15 plants, each reverted), and a banned word in a code span and two em dashes passed. Planted `docs/planning` and `#93` failed gate:15, and a dead link and a `(TODO)` failed gate:19.

- **The seeker and the AIC checklist** (#103, part 4 of #91). At code and at complete the engine holds a run until an independent reader has read its change against the spec and the AIC checklist, and found nothing CRITICAL or HIGH.
  - **The flow:** with every other row green, `workflow:run` answers `inspection-due` (exit 1). The coding agent dispatches the `aic-seeker` subagent with the prompt "Inspect the open run."; the seeker takes its scope from `bin/aic workflow:seeker-brief`, reads the diff and the checklist, and returns one ledger, which the agent pipes to `bin/aic workflow:seeker-report`.
  - **The ledger:** `Inspector:`, `Subject:` (the tree it read) and a table whose every finding cites a checklist id, or `(no findings)`. Anything else is refused with the format, and nothing is recorded. Filing needs a passing gate verdict on that tree.
  - **The proof that it ran:** the guard records each subagent return (PostToolUse `Agent`, a new `returned` hook) with its digest; an independent ledger is counted only when an `aic-seeker` returned exactly it. The guard also refuses any write made inside an `aic-seeker`.
  - **Holds:** open CRITICAL and HIGH findings hold the phase; MEDIUM and LOW are shown. Complete needs an inspection of the delivered tree. The hold spends no retry budget. The record is `seeker_inspection` and `seeker_finding` in the evidence store (schema v3) and a `seeker.filed` event.
  - **The pack:** `.claude/agents/aic-seeker.md` (`model: inherit`), the checklist (A1 to A9 for what only a reader can judge in an AIC app, L1 to L6 from Droost), and the skills' `inspection-due` steps.
  - **The proof:** live Claude Code sessions in a scratch app took a ticket with a module-boundary plant through all four phases: the seeker held it at HIGH, the agent fixed it, and the seeker marked it resolved. By hand, every malformed ledger and every dispatch case was refused as specified. The probe (`workflow/probes/seeker-checklist.sh`) caught A1 3 of 3, A3 2 of 2 valid reads, A7 3 of 3, and the clean control drew no finding.

- **The code index** (#106, part 7 of #91, first half). An agent asks AIC's own code before it plans, and the run keeps a record of what it asked.
  - **The index:** php-parser over every file git lists (and an app's installed framework), plus the build's surface (routes with their kinds, commands, jobs, modules with their requires and exports), in `var/index/code.sqlite`. A refresh re-parses only what changed; this repository indexes in under a second.
  - **The commands:** `bin/aic code:index [--full]`, `code:tree` (systems with their layers, modules with their requires, dependents and routes, or one module, system or path outlined), `code:search <text>` and `code:refs <name>` (what refers to a symbol and what it refers to, or the candidates for a short name). They need no `config/workflow.php`, and every query refreshes the index first.
  - **The log:** while a run is open, each lookup appends a `code.queried` event (the files and scopes it showed) to the run's event log, which #102's guard walls. #118's plan check reads them.
  - **Boundaries:** `AIC\Workflow\Parsing\` is the only Deptrac layer that may reach php-parser. gate:2 admits `nikic/php-parser` for `workflow/composer.json` alone. Both were seen to fail on plants.

- **House rules** (#104, part 5 of #91). The workflow engine holds every run to the project's house rules: PHP files that judge the run's change, base against head, where the gate suite judges the tree.
  - **Declared** in `config/workflow.php` as `HouseRule`s. Each runs as its own process: `aic.house-rule/1` JSON on stdin, with base copies the engine writes so the rule runs no git. Exit 0 holds, 1 breaks, 4 defers (never a pass); a timeout, a missing file or any other exit did not run.
  - **Frozen:** `rule_files` (config/workflow.php, each rule and its probe directory, by sha256) is set at begin in run.json and `run.started`, and walled by the guard. A change holds the run (`rules`).
  - **Probed:** plan runs each rule on its `held-*` and `broken-*` cases (`probes`). A rule that does not bite holds plan for the operator. Code, check and complete run one `rule:<id>` per rule, and criteria may cite them.
  - **Shipped:** `gate-suite` (the gate runner, the gates' code and the tools' configs stay as they began; a module's PSR-4 line and PHPCS root are free) and `raw-html-grants` (no RawHtml grant added, raised or reworded). gate:28 runs their probes in AIC's own suite.
  - **The proof:** a scratch project showed the freeze, both rules failing on their plants, a deferral that holds nothing and cannot be cited, and six broken rules holding plan. gate:28 failed on a planted fixture. 29 gates green.
  - **Split:** `bin/aic workflow:probe`, the sweep that replays #101's planted cases, is #119.

- **The workflow's guard hook** (#102, part 3 of #91). A Claude Code hook holds the agent to the open run between `workflow:run` calls.
  - **The hook:** `workflow/bin/aic-guard.sh` (a shim) runs a PHP entry over `Guard/` classes; `workflow/pack/hooks.json` wires `edit` (Write, Edit, MultiEdit, NotebookEdit and any `mcp__*` tool), `shell` (Bash), `record` (every other tool) and `stop`. A crash refuses; `record` allows.
  - **The walls:** writes go only where the phase allows: no run, the ticket directory; plan, the spec; code, check and complete, the spec and the File Manifest; never the build's outputs. The run's state, the opt-in, the hook wiring, the package and Claude Code's global settings are refused at every phase, through an editor, an MCP path field or the shell. The operator's verbs (`workflow:reset`, a workflow command under a pseudo-terminal or a variable, `composer … --no-dev`) are refused in the agent's shell; a heredoc body is data.
  - **The Stop hold:** a turn does not end mid-phase. A check only the operator can clear is now `Held`: the run waits on the operator (`awaiting`, `run.held`), the agent's `workflow:run` is refused, and the operator's, from a terminal, resumes it (`run.resumed`).
  - **The ledger:** one line per hook call in `var/workflow/guard-calls.jsonl`; `workflow:run` ingests it into `tool_call` (evidence schema v2), so `BrowserCheck` now holds a browser-testable check with no browser call.
  - **Levers:** `enforcement` (frozen into the run) and `requireRun`, each hard (the default), soft (nudge once) or off.
  - **The proof:** probes in a scratch project hit every wall, the hold and the ingest, and a live Claude Code session was refused at plan and held at Stop. 28 gates green.

- **Engine-run gates and evidence** (#101, part 2 of #91). A workflow phase advances only on verdicts the engine measured itself. Each verdict is stored beside the subject hash of the tree it judged, so any later edit makes it stale.
  - **Plan:** the spec must read as a contract: criteria, a `### File Manifest`, and the new `## Entry Points` section of the pipeline template. It is then frozen with the project's gate list.
  - **Code, check and complete** run `composer run gate`, the spec freeze (a rewritten frozen row is a breach), the declaration audit (every changed path, exact, in the manifest) and the composition check (declared entry points against `build/surface.json` and its base-commit version, once gate:24 passed on the tree). Check and complete add the rendered check against the `site` in `config/workflow.php`; check reuses a gate verdict only while it is fresh; complete holds a deferred gate:21 or gate:23 and verifies each criterion's cited checks.
  - **`bin/gate-runner.sh`** prints one `gate-result: gate:N passed|deferred|failed` line per gate before the summary. A run whose lines, summary, exit code and frozen gate list disagree did not reach a verdict.
  - **The store:** `var/workflow/evidence.sqlite` (pdo_sqlite, schema v1). `maxGateRetries` failures of one check at a phase leave the phase to the operator.
  - **The proof:** a scratch clone ran three tickets through every planted case: an undeclared file; a stale verdict re-run; a Page built as an Api; a route built and not declared; a reworded criterion; gate:23 deferred at code and at complete; a killed gate run; a route answering 500; a spent retry budget. 28 gates green.

- **The workflow's run engine** (#100, part 1 of #91). `aic/workflow`, a dev-only package in `workflow/`, runs one ticket through plan, code, check and complete, one phase per `bin/aic workflow:run <ticket>` call, and only the engine writes the run's state.
  - **State:** `var/workflow/run.json` (schema v1, read strictly: bad JSON or an unknown key is refused by name and left as it is), the append-only `events.jsonl` in `aic.run-event/1` (`workflow/schema/run-event.v1.json`; a torn last line is skipped) and `history/` with each finished run and its spec.
  - **The ticket** moves with the run (`in-progress` with its phase, then `in-review` at `docs`), written the way `bin/ticket.sh` writes it. The plan phase's one check is that the spec exists; the engine-run gates and the rest of #91 arrive with #101 to #106.
  - **Commands:** `workflow:run`, `workflow:status`, and `workflow:reset`, which runs only from a terminal. An app opts in with `config/workflow.php`; without it every command refuses.
  - **Boundaries:** two phpat rules keep runtime code off the workflow and the workflow off everything but the Command kind; each failed on its plant. Every class tool reads `workflow/src`; gate:21 does not, since the package runs interpreted (430 classes, unchanged).
  - **The proof:** a scratch project ran a ticket to `completed` in four calls with 20 events, and every refusal exited 2 and wrote nothing. 28 gates green.

- **Components only, and RawHtml counted** (#99, part 2 of #87). No code path but the Renderer can make HTML, and the one sanctioned way round it is granted per class and counted.
  - **gate:8 rules:**
    - `aic.htmlConstruction`: `new Html` only in the Renderer, aliases and class-strings included.
    - `aic.htmlMarkupRead`: `->markup()` only in `Psr7ResponseWriter`, nullsafe and first-class callables included.
    - `aic.controllerMarkupLiteral`: no string holding `<` in a module's `src/Controller/`.
    - `aic.controllerReturnType`: a controller's methods return its kind's response only, so `JobsPage`'s line helper moved to `ScheduleLines`.

  - **gate:27:** `bin/gate-raw-html.php` lists every `new RawHtml` with its place and reason and holds each module class to its `RawHtmlGrant` in `config/raw-html.php`: an exact count and a reason. It refuses `RawHtml::` outside the Renderer. The demo grants nothing.

- **One Renderer makes HTML** (#98, part 1 of #87). Components are data: `Component` declares no method, a component is its public props and its template, and no controller, service, form or block builds markup.
  - **The Renderer:** `AIC\Component\Application\Renderer` is the only code that makes an `Html`, and `Psr7ResponseWriter` the only code that reads one. It writes a page's layout, regions, components and blocks through a `RenderPass`, which keeps Tessera's `<!--t:c-->` markers, keys and props tokens exactly as #37 and #70 spell them.
  - **Fragments by path:** a Tessera fragment is the same tree rendered by its path (`content/c0/NoteList.1`), so `ComponentRuns`, `Marker` and `Run` are gone. gate:23 gains that step (73).
  - **The lookup:** `composer run build` generates `ModuleTemplates` and one `<M>Templates` per module, ending at the atoms' hand-written templates (`AtomTemplates`, `ControlTemplates`, `FormTemplates`). It refuses a module component with no template.
  - **Templates** compile to `render(X, RenderPass): string`: a component through `child()` (`inline()` in a layout), a `Region` through `region()`. An `Html` echo is refused until #99.
  - **The demo:** pages hand `HtmlLayout::content()` a list of components, and form services return `Form` values. New atoms `Heading`, `Paragraph`, `HiddenInput` and `TrackedAssets`; new module components `SiteNav`, `Ticks`, `ContentPages`, `Greetings`, `Home`, `LineList`, `StockListing`, `StockLinks` and `FaqList`; `ContentViews` holds the page editor and its 404.
  - **The proof:** a crawl of 84 requests against main abc2964 found every page and fragment byte-identical (41) or equal once Tessera markers are stripped (43), the note pages' regions exact; 27 gates green; the browser check on DDEV and on the compiled site.
  - **Follow-ups:** #113 (an elephc carry: the template lookups use `if` chains), #114 (the atoms as templates), #115 (the tick stream's markup).

- **Plain PHP templates compile** (#97, part 2 of #88). `composer run build` compiles each gate:25-valid `*.html.php` into the `XTemplate.php` beside its component, and the `.tpl` grammar, `TemplateParser` and `TemplateLines` are gone.
  - **Static types:** the reader types every expression from the component's declarations, by reflection and the constructor's `@param list<T>` (through `phpstan/phpdoc-parser`, a new `require-dev`).
  - **Escaping by type:** a string is escaped; a number is cast, then escaped; `Html` is written raw; a `Region` as it renders; a component between `Name.N` markers, keyed by its `Keyed` key inside a loop. A list, a bool or any other object is refused.
  - **Real loops:** `foreach` and `for` compile to loops that append with `.=`, so `break` and `continue` mean what PHP means, and block markers stay balanced. `empty()` lowers by type, and a null test on a value that cannot be null is refused.
  - **Refusals:** each is `path:line: category: detail` (class name, property, loop type, condition type, echo type, component key, component type, not compilable). A loop part that would pass PHPCS's length or complexity limit is refused too.
  - **The four templates** (`NoteCard`, `NoteList`, `ContentArticle`, `AppLayout`) are now `.html.php`. Their components are data: promoted public props, built by `NoteViews::noteList()`, `ContentShowPage` and `HtmlLayout`. `Regions::region()` gives a layout its regions. The pages render the same bytes as before.

- **gate:25, the plain PHP template grammar** (#96, part 1 of #88). `bin/gate-templates.php` parses every `*.html.php` under `modules/` and `templates/` with php-parser (now a direct `require-dev`) and refuses, with file and line, every construct outside Chad's grammar, deny by default.
  - **The grammar:** inline HTML, `<?= ?>` with one expression, the alternative control syntax for `if`, `switch`, `for` and `foreach`, `match`, the component variable its typing line names, and loop variables. Property and array reads, literals, comparisons, logic, `??`, `?:`, `isset()`, `empty()`, concatenation, arithmetic, enum cases and class constants.
  - **Refused:** no function at all (the allow-list starts empty), no method or static call, no `::class`, no `new`, no assignment but a `for` counter, no `while` or `do`/`while`, and everything else.
  - **Placement:** a template sits in a module's `templates/components/` or in `templates/layouts/`.
  - **The class tools skip templates.** PHPStan, Psalm, PHPCS, PHPMD, Pint, Rector, Deptrac, phpcpd, semgrep, the dynamic-require scan and the Stop hooks leave them to gate:25 (Chad, 2026-10-21).
  - **The proof:** 38 planted templates each gave their one line. Two valid templates in the tree left all 27 gates green. gate:25 deferred until #97 converted the `.tpl` templates.
  - `FileLister` now lists files for both the asset orphans and the template finder.

- **Module assets, bundled at build** (#95, part 4 of #90). The site theme moves from `theme/` to the top-level `assets/`, which holds CSS only, and each module may bring `modules/<name>/assets/`.
  - **The stylesheet:** `composer run build` writes one `public/assets/aic.css` at the same URL: a header, each module's CSS by file name with the modules in requires order, then the theme last, so the site's theme has the final word. Each part sits behind a comment naming its file.
  - **The copies:** a module's other assets are copied byte for byte to `public/assets/<module>/<file>` and committed. Scripts are copied and never linked (Chad); a component that needs one declares it from #55.
  - **What the build refuses:** a subfolder (flat until #55), a name or extension the compiled site does not serve, a non-CSS file in the theme, `@import` and a relative `url()`.
  - **gate:24:** it names a stale bundle, a missing copy and an orphan under `public/assets/`, and the build deletes orphans there and nowhere else. `AssetBundle`, `ModuleAssets`, `BundledCss` and `PublicAssetOrphans` replace `ThemeBuild`.
  - **The demo:** the `#site-nav` rules move to `modules/site/assets/site.css`, and `modules/site/assets/favicon.svg` is linked from the layout, which ends the `/favicon.ico` 404 on every page. gate:23 fetches it on both runtimes (72 steps), and gate:26's shell allows `assets/` in place of `theme/`.

- **gate:26, the module boundaries** (#94, part 3 of #90). `bin/gate-modules.php` reads the module manifests, `git ls-files -co --exclude-standard`, each PHP file's symbols, the build's template classes and composer.json's `App\` prefixes, then holds five rules.
  - **R1:** a class's kind decides its `src/` folder, at any depth, and a kind folder holds only its kind. The kinds come from the interfaces through `Gates\Domain\ClassKinds`, which the surface manifest now shares; Repository and Form go by name suffix. A plain class sits in `Entity/`, `Service/` or `Form/`, and a module's root holds only its manifest, `src/`, `templates/components/`, `assets/` and `resources/`.
  - **R2:** at most 15 files per folder; `src/Migration/` is exempt.
  - **R3:** a module uses another's class only when that module exports it and this one requires that module.
  - **R4:** the requires name modules and form no cycle, through the build's own `ModuleGraph`, whose cycle message now names only the cycle.

- **Routing and the PSR-15 stack** (#19, the third slice of #4). Routes are declared in `config/routes.php` (`RouteCollector::onGet()`, `{name}` and `{name:int|slug|uuid|any}` placeholders) and matched by `AIC\Routing\Domain\RouteTable`: the fewest parameters win, HEAD answers on GET routes, and a miss answers 404, or 405 with `Allow`, through `RouteErrorMiddleware`. The router hands the matched handler the request with its parameters as attributes. `AIC\Middleware\Application\MiddlewareStep` chains PSR-15 middleware. `ResponseBuilder` makes responses. The app's first handlers live in `app/Http`, so every gate now runs with no deferral. All 39 runtime classes compile natively.
- **HTTP with typed input** (#20, the second slice of #4). PSR-7 messages and PSR-17 factories (`AIC\Http`), and the SAPI request and response (`AIC\Frankenphp`): the worker narrows `$_SERVER`, the extractor builds the request, and the response goes out through the emitter and a SAPI sink the worker implements. A query or form field is a string, a list or a map of strings; deeper nesting answers 400. Headers are stored flat and refuse line breaks. `mixed` appears only on PSR overrides; semgrep's phpdoc rule gained the `#[Override]` exemption PHPCS has (Chad). All 21 runtime classes compile natively.
- **Typed config** (#18, the first slice of #4). `config/app.php` returns an `AIC\Config\Domain\AppConfig`, a `final readonly` object whose `name` must not be blank. The worker requires the file once, at boot, and renders the name. Config files are analysed like code. `AppConfig` is the first runtime class since #15, so the native gate runs again.

### Changed

- **Component and block markers are Tessera's** (#70): `<!--t:c KEY-->` … `<!--/t:c-->` in place of `<!--aic:c ...-->`, and `<!--t:b-->` … `<!--/t:b-->` in place of `aic:if` and `aic:each`. Region keys are `cN` (or a `KeyedComponent`'s), template keys `Name.N` and `Name.N:BINDING`.
- **Mixed values at array and object boundaries** (#54, fork PR #14, c114cb89a). elephc now passes a `mixed` value to a declared `array`, `?array` or class-typed parameter or return and checks it at run time with PHP's `TypeError`, so `ServerRequest::withParsedBody()` hands the array straight to `withQueryParams()`, and `UploadCheck::check()` returns the first matching kind's label from a plain loop. Narrowing that validates input stays. plan.md's Mixed values rule now lists only what elephc still refuses: `iterable`, closures held in variables or called through `call_user_func`, and `array_combine` over `array_map` results.
- **The native workarounds whose compiler fixes landed are gone** (#53). Fork PRs #10 to #12 made several shapes compile, so AIC code no longer works around them:
  - `UploadedFile::moveTo` renames the upload, now that `rename()` crosses filesystems (#45).
  - `PageHandler` and `ContentShowPage` call the narrowed value directly, since `instanceof` narrows an interface-typed value (#40).
  - The notes citing those gaps are gone.
  - plan.md's native-style rules list only what still fails, and record what compiles now.
- **Dead-code detection** (#15). `shipmonk/dead-code-detector` replaces the abandoned `tomasvotruba/unused-public` in gate:8. It checks methods, constants, enum cases, and properties never read or written; dead cycles and transitively dead methods; and it does not count a call over an unknown type as usage. gate:0 reports no abandoned package. The gate classes lost their `@api` tags, which had hidden their members from both dead-code checks. The detector found the unused `RelativePathComputer` (deleted) and the caller-less `AIC\Routing\Domain\Method` cases (the class waits for #4). gate:21 defers until runtime code returns.

### Fixed

- **Hook checks on long transcripts** (#16). Every early-exit reader fed by a pipe in `.claude/hooks/` and `bin/` (`grep -q`, `grep -m`, `head`; 15 sites in 8 scripts) now reads a here-string or a process substitution, or `awk 'NR == 1'` takes the first line. Under `pipefail` such a pipe fails once its input outgrows the pipe buffer, as PR #11 found in `enforce-completion.sh`. The semgrep rule `aic-no-early-exit-pipe` (gate:15, which now scans the hooks) keeps the pattern out. The completion hook's block message says how to test a block against the transcript; there is no ceiling on repeated blocks.
- **Completion evidence on a long session** (#3, found live). `enforce-completion.sh` piped the session's command list into `grep -q` under `pipefail`. Past the pipe buffer, `grep -q` exits on its first match, `echo` takes SIGPIPE, and the pipeline fails (141), so a gate run that happened read as missing and Stop blocked in a loop. The checks read a here-string now.
- **Memory in Documentation** (#3, found by #15). `/pipeline:complete`'s write scope now includes the project's auto-memory directory. Its memory step writes there, and the scope hook blocked it.
- **Hook project root** (#3, found live). The hooks take the root from `$CLAUDE_PROJECT_DIR`, falling back to the git root. Starting from the session's working directory found the nested planning repo whenever the shell sat in `docs/planning`, and the MCP-config hook then blocked every write.
- **Hook command detection** (#3). Old AIC's hooks recognized only Skill-tool invocations of the workflow commands. A command the user typed is recorded as `<command-name>/…</command-name>`, so it never made a session a pipeline session.
- **Two hook checks that never ran** (#3). The SAST hook's semgrep check looked for `.semgrep.yml` and the quality hook's PHPCS check for `phpcs.xml`; the real files are `semgrep.yml` and `phpcs.xml.dist`.

- **Git hooks on old commits** (#2). Only the enabled git hooks are installed. A disabled hook still ran captainhook, which failed on any checkout older than `captainhook.json`.
