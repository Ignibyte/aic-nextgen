# Changelog

Every delivered pipeline adds an entry here with its ticket number (`/pipeline:complete`). Tickets live in the private planning repo; old AIC's are cited as "AIC #N".

## Unreleased

### Added

- **The workflow's guard hook** (#102, part 3 of #91). A Claude Code hook holds the agent to the open run between `workflow:run` calls.
  - **The hook:** `workflow/bin/aic-guard.sh` (a shim) runs a PHP entry over `Guard/` classes; `workflow/pack/hooks.json` wires `edit` (Write, Edit, MultiEdit, NotebookEdit and any `mcp__*` tool), `shell` (Bash), `record` (every other tool) and `stop`. A crash refuses; `record` allows.
  - **The walls:** writes go only where the phase allows: no run, the ticket directory; plan, the spec; code, check and complete, the spec and the File Manifest; never the build's outputs. The run's state, the opt-in, the hook wiring, the package and Claude Code's global settings are refused at every phase, through an editor, an MCP path field or the shell. The operator's verbs (`workflow:reset`, a workflow command under a pseudo-terminal or a variable, `composer … --no-dev`) are refused in the agent's shell; a heredoc body is data.
  - **The Stop hold:** a turn does not end mid-phase. A check only the operator can clear is now `Held`: the run waits on the operator (`awaiting`, `run.held`), the agent's `workflow:run` is refused, and the operator's, from a terminal, resumes it (`run.resumed`).
  - **The ledger:** one line per hook call in `var/workflow/guard-calls.jsonl`; `workflow:run` ingests it into `tool_call` (evidence schema v2), so `BrowserCheck` now holds a browser-testable check with no browser call.
  - **Levers:** `enforcement` (frozen into the run) and `requireRun`, each hard (the default), soft (nudge once) or off.
  - **The proof:** probes in a scratch project hit every wall, the hold and the ingest, and a live Claude Code session was refused at plan and held at Stop. 28 gates green.

- **Engine-run gates and evidence** (#101, part 2 of #91). A workflow phase advances only on verdicts the engine measured itself. Each verdict is stored beside the subject hash of the tree it judged, so any later edit makes it stale.
  - **Plan:** the spec must read as a contract: criteria, a `### File Manifest`, and the new `## Entry Points` section of the pipeline template. It is then frozen with the project's gate list.
  - **Code, check and complete** run `composer run gate`, the spec freeze (a rewritten frozen row is a breach), the declaration audit (every changed path, exact, in the manifest) and the composition check (declared entry points against `build/surface.json` and its base-commit version, once gate:24 passed on the tree). Check and complete add the rendered check against the `site` in `config/workflow.php`; check reuses a gate verdict only while it is fresh; complete holds a deferred gate:21 or gate:23 and verifies each criterion's cited checks.
  - **`bin/gate-runner.sh`** prints one `gate-result: gate:N passed|deferred|failed` line per gate before the summary. A run whose lines, summary, exit code and frozen gate list disagree did not reach a verdict.
  - **The store:** `var/workflow/evidence.sqlite` (pdo_sqlite, schema v1). `maxGateRetries` failures of one check at a phase leave the phase to the operator.
  - **The proof:** a scratch clone ran three tickets through every planted case: an undeclared file; a stale verdict re-run; a Page built as an Api; a route built and not declared; a reworded criterion; gate:23 deferred at code and at complete; a killed gate run; a route answering 500; a spent retry budget. 28 gates green.

- **The workflow's run engine** (#100, part 1 of #91). `aic/workflow`, a dev-only package in `workflow/`, runs one ticket through plan, code, check and complete, one phase per `bin/aic workflow:run <ticket>` call, and only the engine writes the run's state.
  - **State:** `var/workflow/run.json` (schema v1, read strictly: bad JSON or an unknown key is refused by name and left as it is), the append-only `events.jsonl` in `aic.run-event/1` (`workflow/schema/run-event.v1.json`; a torn last line is skipped) and `history/` with each finished run and its spec.
  - **The ticket** moves with the run (`in-progress` with its phase, then `in-review` at `docs`), written the way `bin/ticket.sh` writes it. The plan phase's one check is that the spec exists; the engine-run gates and the rest of #91 arrive with #101 to #106.
  - **Commands:** `workflow:run`, `workflow:status`, and `workflow:reset`, which runs only from a terminal. An app opts in with `config/workflow.php`; without it every command refuses.
  - **Boundaries:** two phpat rules keep runtime code off the workflow and the workflow off everything but the Command kind; each failed on its plant. Every class tool reads `workflow/src`; gate:21 does not, since the package runs interpreted (430 classes, unchanged).

- **One Renderer makes HTML** (#98, part 1 of #87). Components are data: `Component` declares no method, a component is its public props and its template, and no controller, service, form or block builds markup.
  - **The Renderer:** `AIC\Component\Application\Renderer` is the only code that makes an `Html`, and `Psr7ResponseWriter` the only code that reads one. It writes a page's layout, regions, components and blocks through a `RenderPass`, which keeps Tessera's `<!--t:c-->` markers, keys and props tokens exactly as #37 and #70 spell them.
  - **Fragments by path:** a Tessera fragment is the same tree rendered by its path (`content/c0/NoteList.1`), so `ComponentRuns`, `Marker` and `Run` are gone. gate:23 gains that step (73).
  - **The lookup:** `composer run build` generates `ModuleTemplates` and one `<M>Templates` per module, ending at the atoms' hand-written templates (`AtomTemplates`, `ControlTemplates`, `FormTemplates`). It refuses a module component with no template.
  - **Templates** compile to `render(X, RenderPass): string`: a component through `child()` (`inline()` in a layout), a `Region` through `region()`. An `Html` echo is refused until #99.
  - **The demo:** pages hand `HtmlLayout::content()` a list of components, and form services return `Form` values. New atoms `Heading`, `Paragraph`, `HiddenInput` and `TrackedAssets`; new module components `SiteNav`, `Ticks`, `ContentPages`, `Greetings`, `Home`, `LineList`, `StockListing`, `StockLinks` and `FaqList`; `ContentViews` holds the page editor and its 404.
  - **The proof:** a crawl of 84 requests against main abc2964 found every page and fragment byte-identical (41) or equal once Tessera markers are stripped (43), the note pages' regions exact; 27 gates green; the browser check on DDEV and on the compiled site.
  - **Follow-ups:** #113 (an elephc carry: the template lookups use `if` chains), #114 (the atoms as templates), #115 (the tick stream's markup).

- **Plain PHP templates compile** (#97, part 2 of #88). `composer run build` compiles each gate:25-valid `*.html.php` into the `XTemplate.php` beside its component, and the `.tpl` grammar, `TemplateParser` and `TemplateLines` are gone.
  - **Static types:** the reader types every expression from the component's declarations, by reflection and the constructor's `@param list<T>` (through `phpstan/phpdoc-parser`, a new `require-dev`).
  - **Escaping by type:** a string is escaped; a number is cast, then escaped; `Html` is written raw; a `Region` as it renders; a component between `Name.N` markers, keyed by its `Keyed` key inside a loop. A list, a bool or any other object is refused.
  - **Real loops:** `foreach` and `for` compile to loops that append with `.=`, so `break` and `continue` mean what PHP means, and block markers stay balanced. `empty()` lowers by type, and a null test on a value that cannot be null is refused.
  - **Refusals:** each is `path:line: category: detail` (class name, property, loop type, condition type, echo type, component key, component type, not compilable). A loop part that would pass PHPCS's length or complexity limit is refused too.
  - **The four templates** (`NoteCard`, `NoteList`, `ContentArticle`, `AppLayout`) are now `.html.php`. Their components are data: promoted public props, built by `NoteViews::noteList()`, `ContentShowPage` and `HtmlLayout`. `Regions::region()` gives a layout its regions. The pages render the same bytes as before.

- **gate:25, the plain PHP template grammar** (#96, part 1 of #88). `bin/gate-templates.php` parses every `*.html.php` under `modules/` and `templates/` with php-parser (now a direct `require-dev`) and refuses, with file and line, every construct outside Chad's grammar, deny by default.
  - **The grammar:** inline HTML, `<?= ?>` with one expression, the alternative control syntax for `if`, `switch`, `for` and `foreach`, `match`, the component variable its typing line names, and loop variables. Property and array reads, literals, comparisons, logic, `??`, `?:`, `isset()`, `empty()`, concatenation, arithmetic, enum cases and class constants.
  - **Refused:** no function at all (the allow-list starts empty), no method or static call, no `::class`, no `new`, no assignment but a `for` counter, no `while` or `do`/`while`, and everything else.
  - **Placement:** a template sits in a module's `templates/components/` or in `templates/layouts/`.
  - **The class tools skip templates.** PHPStan, Psalm, PHPCS, PHPMD, Pint, Rector, Deptrac, phpcpd, semgrep, the dynamic-require scan and the Stop hooks leave them to gate:25 (Chad, 2026-10-21).
  - **The proof:** 38 planted templates each gave their one line. Two valid templates in the tree left all 27 gates green. gate:25 deferred until #97 converted the `.tpl` templates.
  - `FileLister` now lists files for both the asset orphans and the template finder.

- **Module assets, bundled at build** (#95, part 4 of #90). The site theme moves from `theme/` to the top-level `assets/`, which holds CSS only, and each module may bring `modules/<name>/assets/`.
  - **The stylesheet:** `composer run build` writes one `public/assets/aic.css` at the same URL: a header, each module's CSS by file name with the modules in requires order, then the theme last, so the site's theme has the final word. Each part sits behind a comment naming its file.
  - **The copies:** a module's other assets are copied byte for byte to `public/assets/<module>/<file>` and committed. Scripts are copied and never linked (Chad); a component that needs one declares it from #55.
  - **What the build refuses:** a subfolder (flat until #55), a name or extension the compiled site does not serve, a non-CSS file in the theme, `@import` and a relative `url()`.
  - **gate:24:** it names a stale bundle, a missing copy and an orphan under `public/assets/`, and the build deletes orphans there and nowhere else. `AssetBundle`, `ModuleAssets`, `BundledCss` and `PublicAssetOrphans` replace `ThemeBuild`.
  - **The demo:** the `#site-nav` rules move to `modules/site/assets/site.css`, and `modules/site/assets/favicon.svg` is linked from the layout, which ends the `/favicon.ico` 404 on every page. gate:23 fetches it on both runtimes (72 steps), and gate:26's shell allows `assets/` in place of `theme/`.

- **gate:26, the module boundaries** (#94, part 3 of #90). `bin/gate-modules.php` reads the module manifests, `git ls-files -co --exclude-standard`, each PHP file's symbols, the build's template classes and composer.json's `App\` prefixes, then holds five rules.
  - **R1:** a class's kind decides its `src/` folder, at any depth, and a kind folder holds only its kind. The kinds come from the interfaces through `Gates\Domain\ClassKinds`, which the surface manifest now shares; Repository and Form go by name suffix. A plain class sits in `Entity/`, `Service/` or `Form/`, and a module's root holds only its manifest, `src/`, `templates/components/`, `assets/` and `resources/`.
  - **R2:** at most 15 files per folder; `src/Migration/` is exempt.
  - **R3:** a module uses another's class only when that module exports it and this one requires that module.
  - **R4:** the requires name modules and form no cycle, through the build's own `ModuleGraph`, whose cycle message now names only the cycle.
  - **R5:** nothing outside `modules/` but the shell (`generated/`, `config/`, `bootstrap/`, `public/`, `templates/layouts/`, `theme/`, `build/`, the console and the build, this repo's framework and tooling, and the root files by name). Every `App\` prefix maps a module's namespace to its `src/`, and no PHP outside `modules/` and `generated/` declares an `App\` class.

  Each breach is one line naming the folder, the `->export(...)` or the `->requires(...)` to add. There is no deferral: an unreadable tree fails the gate. All 13 plants and the fail-closed read were seen to fail. The stock list's builder, `StockList`, moved from `src/Component/` to `src/Service/`, because it makes a component rather than being one.

### Changed

- **The demo app is ten modules** (#93, part 2 of #90). `app/`, `resources/`, `config/routes.php` and every hand-written composition class are gone. The demo's features are now the modules site, home, greeting, note, session, auth, content, job and stock, beside faq. Each class sits in `modules/<name>/src/<Kind>/` as `App\<Name>\<Kind>\`, migrations in `src/Migration/`; component templates are in `modules/<name>/templates/components/`, the page layout in `templates/layouts/`, the downloads in `modules/site/resources/`.
  - **The manifest is a fluent value.** A manifest returns `(new ModuleManifest('<name>'))` with a wither per declaration: `requires`, `route`, `binding`, `block`, `plugin`, `migration`, `export`, `command`, `job`, `schedule`, `middleware` (with a `MiddlewarePosition`, today `AfterSession`), `protectedPrefix` and `factory`. It replaces #92's anonymous class implementing `Module`, and it holds a list of `ModuleDeclaration`s.
  - **New contract pieces.** A plugin list reaches a constructor through `#[Tagged(Type::class)]` on its parameter. A factory is a readonly module class whose methods return services built from values, matched by return type: `UploadRules` for the upload check, `AccessRules` for the sign-in config, which it builds from every module's protected prefixes.
  - **`generated/`.** The wiring moved from `app/Generated/` to `generated/` (`App\Generated\`) and gained `<M>Middleware`, `<M>Commands`, `<M>Jobs`, `<M>Schedules` and `<M>Prefixes`, their aggregators, and the facades `WebModules` and `ConsoleModules`. A generated class takes the context only when an object in it reads a root; the facade implements `RootlessCommandWiring`, `RootlessJobWiring` or `RootlessMiddlewareWiring` for a kind that reads none.   - **Framework kernels.** `AIC\Module\Application\AppKernel` composes the framework's own web wiring from the facade: the plugins, the handler context, the router, and the stack with the modules' middleware after the session. `ConsoleKernel` adds `migrate`, `migrate:status`, `queue:work`, `schedule:run`, the `notify` job and the framework's migrations, applied first, to the modules'. `bootstrap/serve.php`, `bin/aic` and `bin/aic-build` build only through them.

  - **What stayed the same.** `build/surface.json` lists the same 36 routes, 7 commands, 2 jobs and schedule, every route a module's; all 16 migrations stay applied with unchanged checksums; gate:23 matches PHP on all 71 steps.
  - **Gates and hooks.** gate:4 waits for source in `modules/`, and every tool and gate root names `modules/` and `generated/`. Found and filed: the elephc carry #112, which `AppKernel` and `ConsoleKernel` work around with an `if` per interface.

### Added

- **Column changes on an applied table** (#86, Lotline #26). `TableAlteration` gained `addColumn(name, ColumnType)` with `nullable()`, and `changeType(column, ColumnType, using = '')`, compiled one `ALTER TABLE` each. Column types come from `Schema::types()` (`ColumnTypes`, one method per type `TableBuilder` declares), which `TableBuilder` now builds from too; applied checksums are unchanged. The demo's `stock_items` gains a cost and a count date, then converts them to `numeric(10, 2)` and `date` as Lotline's vehicles need. The framework's migrations are listed in `App\FrameworkMigrations`, applied first.
- **Tessera props tokens** (#74, a child of #12). `KeyedComponent` takes a props token, an `EnvelopeCodec` envelope of the component's inputs, and `Region` renders `<!--t:c KEY TOKEN-->`; `TesseraProps::forTarget()` reads the token Tessera sends back in `Tessera-Targets` and verifies it through the new `EnvelopeCodec::openToken()`, so an altered token is refused. The demo's stock list keeps its `limit` across a refresh. PHPStan caches in `.phpstan-cache/` (each config its own), out of the shared temp directory. gate:23 sends an altered token (68 steps).
- **Tessera streams** (#73, a child of #12). Event streams send protocol 7's headers (`Cache-Control: no-store`, `Tessera-Protocol: 0`, `Vary`); `ServerEvent` takes an `id` and a nameless event is a `: keep-alive` comment; `TesseraEvents` builds `tessera-patch-elements` and `tessera-patch-signals`; every finished stream ends with `tessera-close`. `/events` sends Tessera ticks with ids and a signal per tick and resumes after `Last-Event-ID`; the new `/ticks` page fills live from it. gate:23 compares two resumed streams (67 steps).
- **Repeated writes by Tessera-Write-Id** (#72, a child of #12). A write carrying `Tessera-Write-Id` is applied once per visitor: the first copy runs and its answer is recorded in `aic_tessera_writes` (a framework migration), a repeat within ten minutes gets that answer again, or `409` while the first is unsettled, and a malformed id gets `400`. Ids are scoped by a hash of the session's CSRF token. `App\TesseraStack` composes Tessera's middleware. gate:23 repeats a write (65 steps). Found and filed: the elephc carry #78.
- **Tessera's forms and redirects** (#71, a child of #12). Every redirect answering a Tessera request becomes `200` with `Tessera-Location`, its cookies kept (`TesseraRedirectMiddleware`); `PageFullVisit` sends `Tessera-Full-Visit` (logout uses it). Submissions and actions are answered with fragments at the page's status, so a refused form comes back as a `422` region; error alerts carry `data-error-summary` and `Input` an `aria-invalid` flag; `PageDocument` allows `409`. A visit brings the layout's other regions too, and every fragment response renews the CSRF meta. The guard answers a Tessera request's stale token with `419`. The demo is enhanced throughout; links to non-HTML answers opt out. gate:23 sends three Tessera writes (62 steps).
- **Tessera's server side, slice 1** (#70, a child of #12, for Lotline #10). The head carries the `tessera-layout`, `tessera-csrf-token` and `tessera-csrf-header` metas and `data-track` on the stylesheet and the script. Components and blocks render Tessera's `<!--t:c KEY-->` and `<!--t:b-->` markers with keys in its grammar (`KeyedComponent`, `cN`, `Name.N`, `Name.N:ID`). A request in another protocol gets `400` (`TesseraProtocolMiddleware`); a visit or refresh whose targets all exist under the same layout gets a fragment response (`text/vnd.tessera+html`, one `<template data-target>` per region or component path); every page response carries `Vary` on Tessera's headers. The demo keeps enhancement off until #71, except the nav and the stock list's refresh link. gate:23 sends five Tessera requests (59 steps). Found and filed: the elephc carry #75.
- **Blocks render for the request** (#58, from Lotline #14). `Block` is no longer a component: `component(ServerRequestInterface): Component` makes what it shows on the page it is placed into, and `Blocks::place()` and `PageDocument::withBlocks()` take the request. `Link` takes an optional `current` flag that writes `aria-current="page"`. Found and filed: the elephc carry #69.
- **A kind method may leave its dictated parameter unread** (#56, from Lotline #13). gate:10 and gate:11 run AIC's own wrappers of PHPMD's `UnusedFormalParameter` and Slevomat's `Functions.UnusedParameter`, `Gates\Phpmd\KindAwareUnusedFormalParameter` and `Gates.Functions.KindAwareUnusedParameter`. They let go only the own parameters of a Page, Api, Stream, Command or Job method, by interface and method name, interfaces resolved to full names. Every other unused parameter still fails both, closures inside a kind method included. No suppression, no annotation, no parameter-name pattern. plan.md lists the files and settings an app copies.
- **Date, numeric and boolean columns** (#65, from Lotline #18). `TableBuilder::date()`, `numeric(name, precision, scale)` and `boolean()`; `Row::bool()`; the entity field types Date, Numeric and Boolean. Dates and numerics are strings both ways (`YYYY-MM-DD`, a decimal string), so money never passes through a float. A Boolean field takes a PHP bool, bound as `'true'` or `'false'` because PHP's PDO binds `false` as an empty string. The `Checkbox` atom. The demo's `/stock` adds and lists items with a price, a date and a certified flag, and gate:23 checks the round trip natively (54 steps).
- **Unique constraints and indexes on an existing table** (#66, from Lotline #23). `Schema::alter(table)` returns a `TableAlteration` with `unique()` and `index()`, compiled to one `ALTER TABLE ... ADD UNIQUE (...)` per constraint and a `CREATE INDEX` per index, and checksummed like the rest. `Table` and the new `Alteration` share a `Constraints` value, so `create()`'s statements are unchanged. An alteration that adds nothing is refused. The demo indexes `notes.created_at`, and creates `subscribers` and then makes its email unique.
- **Unique constraints, indexes and foreign keys** (#59, from Lotline #16). `TableBuilder::unique()`, `index()` and `foreignKey(column, table, foreignColumn, OnDelete)`, with `OnDelete` as `Restrict`, `Cascade` or `SetNull`, and `bigInteger()` for a column that refers to an identity. `Table` refuses a constraint or index on a missing column, an empty column list, `SetNull` on a required column and an index name over 63 characters. Unique and foreign keys go into `CREATE TABLE`, and each index follows its table as `CREATE INDEX <table>_<cols>_idx`. Existing migrations compile as before, so their checksums hold. The demo's `note_tags` migration uses all four.

### Changed

- **Component and block markers are Tessera's** (#70): `<!--t:c KEY-->` … `<!--/t:c-->` in place of `<!--aic:c ...-->`, and `<!--t:b-->` … `<!--/t:b-->` in place of `aic:if` and `aic:each`. Region keys are `cN` (or a `KeyedComponent`'s), template keys `Name.N` and `Name.N:BINDING`.
- **Mixed values at array and object boundaries** (#54, fork PR #14, c114cb89a). elephc now passes a `mixed` value to a declared `array`, `?array` or class-typed parameter or return and checks it at run time with PHP's `TypeError`, so `ServerRequest::withParsedBody()` hands the array straight to `withQueryParams()`, and `UploadCheck::check()` returns the first matching kind's label from a plain loop. Narrowing that validates input stays. plan.md's Mixed values rule now lists only what elephc still refuses: `iterable`, closures held in variables or called through `call_user_func`, and `array_combine` over `array_map` results.
- **The native workarounds whose compiler fixes landed are gone** (#53). Fork PRs #10 to #12 made several shapes compile, so AIC code no longer works around them:
  - `UploadedFile::moveTo` renames the upload, now that `rename()` crosses filesystems (#45).
  - `PageHandler` and `ContentShowPage` call the narrowed value directly, since `instanceof` narrows an interface-typed value (#40).
  - The notes citing those gaps are gone.
  - plan.md's native-style rules list only what still fails, and record what compiles now.
- **Dead-code detection** (#15). `shipmonk/dead-code-detector` replaces the abandoned `tomasvotruba/unused-public` in gate:8. It checks methods, constants, enum cases, and properties never read or written; dead cycles and transitively dead methods; and it does not count a call over an unknown type as usage. gate:0 reports no abandoned package. The gate classes lost their `@api` tags, which had hidden their members from both dead-code checks. The detector found the unused `RelativePathComputer` (deleted) and the caller-less `AIC\Routing\Domain\Method` cases (the class waits for #4). gate:21 defers until runtime code returns.

- **Hook checks on long transcripts** (#16).
